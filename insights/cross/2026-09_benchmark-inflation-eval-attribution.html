      信源： Cognition · SWE-2 发布 · Terminal-Bench · 本站每日前沿扫描（2026-09-11）

      核心论点：Cognition 发布 SWE-2，在 Terminal-Bench 2.1 上刷出漂亮新高——但在更新、更贴近真实工作的 Terminal-Bench 4.0 上却明显落后。这不是造假，而是跑分通胀（benchmark inflation）的典型病征：当一个基准变成营销目标，模型就会被优化去讨好这张榜，而不是变得真的更强。分数于是脱离了它本应代表的能力——就像被印多了的钞票脱离了它本应代表的价值。解药不是「再找一张更好的榜」，而是把「一个分数」升级成「一条归因链」：这个分测的是什么任务、在什么条件下、被谁判定、和我的场景差多远。预判：进行中——12 个月内，「可归因的评测」将取代「排行榜名次」，成为技术选型和对外信任的硬通货。
      一页要点
      • 同一个模型，两幅面孔：SWE-2 在旧榜（Terminal-Bench 2.1）领先、在新榜（4.0）落后。你信哪个数，取决于你先看到哪张榜——这本身就是警报。
      • 通胀的机制是「优化目标错位」：当榜单成为发布 KPI，团队会（有意或无意地）朝榜面拟合——刷的是分数，不是能力。这就是古德哈特定律的 AI 版：指标一旦成为目标，就不再是好指标。
      • Benchmark 有半衰期：任何公开榜发布即开始「被拟合」，可信度随时间衰减；越老、越流行的榜，越可能已经通胀。
      • 一个分数是「无归因的结论」：它把「测什么/什么条件/谁判定/离我多远」全压成一个数字，丢掉了做决策真正需要的因果链。
      • 解药是评测归因：把分数拆回可追问的四要素——任务分布、评测条件、判定口径、与自身场景的距离——评测和归因是同一个动作的两半。
      • 自建私有评测集才是护城河：用你真实业务的任务分布做评测，别人没法针对它「刷分」，也最能预测线上表现。
      • 对 FDE 的意义：给客户做选型时，别拿排行榜名次交差；交付一条可归因、可复现、贴合客户场景的评测结论——这正是我们和「跑分搬运工」的分水岭。

      一同一个模型，两张榜两幅面孔#

      — WHY NOW · 一个分数已经自相矛盾

      SWE-2 发布时，最扎眼的不是它多强，而是它同时又强又弱：在 Terminal-Bench 的旧版本（2.1）上刷出领先成绩，在更新、更贴近真实终端工作的 4.0 上却明显落后。同一个模型，在两张本应测同一件事的榜上，给出了相反的结论。当一个分数开始自相矛盾，它就不再是「能力的度量」，而变成了「拟合对象的度量」——它告诉你的不是模型多强，而是它被调去讨好哪张榜。

      二分数是怎么被通胀出来的#

      — 古德哈特定律的 AI 版

      没人需要「作弊」，通胀也会自然发生。机制是古德哈特定律：当一个度量变成目标，它就不再是好的度量。一张榜刚出来时，它和真实能力高度相关；可一旦它成了发布会 PPT 上的 KPI，整个行业就会朝它优化——调数据配比、对齐题型、甚至无意中让训练集沾了榜的分布。刷上去的是分数，涨的却不一定是能力。下面这条链，就是「一张好榜」如何一步步通胀成「一个空数」的过程。

      跑分通胀的四步漂移How a Benchmark Inflates

      从「可信指标」到「被拟合的空数」，中间只隔四步。越流行的榜，走得越快。

      要分清

      通胀不等于造假。大多数时候没有人污染测试集，团队只是理性地朝「会被拿去比较的那张榜」使劲——这恰恰让它更隐蔽、更普遍。所以正确的姿态不是「抓谁作弊」，而是「默认任何单一公开分数都已部分通胀」，再用归因把水分挤出来。

      三解药：把「一个分数」升级成「一条归因链」#

      — 评测与归因是同一个动作的两半

      一个分数是「无归因的结论」——它把「测的什么任务、在什么条件下、被谁判定、离我的场景多远」全压成一个数字，然后要你照单相信。而做决策真正需要的，是这些被压掉的东西。评测的价值不在给出一个数，而在于让这个数可以被追问、被拆解、被映射到你自己的场景。评测和归因，本就是同一个动作的两半。

      旧姿势 · 一个分数
      「SWE-2 拿了榜首」一个数字、一个名次，直接当结论。你无法追问它到底强在哪。
      无法映射到自己它在别人的任务分布上第一，不代表在你的场景第一。
      → 归因
      拆解
      新姿势 · 一条归因链
      测的是什么任务任务分布、难度、样本量——它到底覆盖了哪一片能力。
      在什么条件下工具、上下文、重试、温度——同一模型换条件分数就变。
      被谁判定人工 / 自动 / LLM 裁判？判定口径决定分数含义。
      离我的场景多远榜的任务分布和你的真实业务重合多少——这才是决策依据。
      看到跑分先追问要拆出的东西拆不出时的默认判断
      测的什么任务？任务分布、样本量、发布时间越老越流行 → 假定已通胀
      什么条件下跑的？工具/上下文/重试/温度设置条件不透明 → 分数不可比
      被谁判定？人工 / 自动脚本 / LLM 裁判裁判不明 → 结论打折
      离我多远？与自身任务分布的重合度重合度低 → 名次对我无意义

      四每张榜都有半衰期#

      — 为什么「换一张新榜」治不了本

      有人会说：那就用最新的 Terminal-Bench 4.0 好了。但这只是把时钟拨回起点——任何公开榜，发布即开始被拟合，可信度随时间衰减。4.0 今天可信，是因为它还新、还没被大规模优化；等它成了下一个发布会 KPI，它也会通胀。这就是 benchmark 的「半衰期」：越流行、越老，水分越大。所以真正的解不是追新榜，而是拥有一张别人刷不到的私有榜。

      Benchmark 半衰期Benchmarks Decay After Release

      纵轴是「分数对真实能力的可信度」。公开榜发布时最高，随被拟合而衰减；私有评测集因为别人刷不到，可信度保持平稳。

      别踩的坑

      看到「我们在 XX 榜刷新 SOTA」就下单，等于用一个可能已经通胀的数字替客户做决策。更稳的姿势：把候选模型放到你自己的任务分布上重测一遍——哪怕只有几十条真实样本，也比一个陌生榜的名次更能预测线上表现。

      五对 FDE 的意义#

      — 不做跑分搬运工，做评测归因的人

      下一步（1–2 周）
      • 建一张私有评测集：从客户真实业务里抽 30–100 条代表性任务，定义清楚判定口径——这是刷不到、也最能预测线上的护城河。
      • 选型别交名次：给客户的选型结论，附上「归因四问」的拆解（测什么/什么条件/谁判定/离你多远），而不是一张排行榜截图。
      • 把厂商跑分默认打折：读发布博客里的 SOTA 时，先查这张榜多老、多流行——越老越流行，折扣越大。
      • 让评测可复现：记录评测的工具/上下文/重试/温度等条件，确保结论能被客户和自己复跑——可复现是可信的前提。
      • 把这条能力产品化：「可归因、可复现、贴合场景的评测」本身就是 FDE 能对外收信任溢价的差异化，和 LIFT 的评测归因一体化方向一致。

      六待验证问题#

      1. SWE-2 在两榜的分差，有多少来自「拟合旧榜」、多少来自 4.0 本身更难 / 口径不同？需要拿到两榜的任务分布对比才能定论。
      2. 私有评测集的样本量下限是多少——几十条真的够预测线上，还是会因样本偏差误导？
      3. LLM 裁判（LLM-as-judge）本身会不会也被通胀 / 被讨好？判定层的可信度怎么保证？
      4. 会不会出现「可信度可标注」的评测标准（给每个分数附归因元数据），让跑分不再是裸数字？
