      模型接入被商品化 · Voting With Their Feet

      当一家自研旗舰模型的公司，都开始放全体工程师去用对手的模型，「拥有一个模型」就不再是护城河——护城河上移到了「谁能安全地编排/路由多模型」，下沉到了「谁的模型真能干活」。

      核心论点：2026-09-15，一贯「Gemini 优先、封杀外部编码工具」的 Google，首次放全体工程师用 Anthropic Claude（Opus 5） 做内部开发；前一天，微软把 xAI Grok 加进 Copilot，让 Office 三件套变成一个「多模型货架」。这两步连起来，是一个比任何 benchmark 都硬的信号：「有没有一个好模型」正在从护城河退化成入场券，「模型接入」本身被商品化、被多路复用。当连自研旗舰厂都用脚投票、按任务从货架上挑模型，竞争就必然上移到「谁能安全、可计费、可审计地编排/路由这些模型」（control plane），并下沉到「谁的模型在真实任务里真能干活」（能力事实，而非发布会）。预判：进行中——12 个月内，卖点不再是「我们接了哪个模型」，而是「我们把多模型选型、路由、退出与治理想清楚了」。
      一页要点
      • 被商品化的是「模型接入」，不是「模型能力」：谁家旗舰、接哪个 API 正在变得可替换；真正拉开差距的是「这个模型在你这条业务上到底干不干得成」。
      • 自研厂用脚投票是最硬的信号：Google 花数十亿做 Gemini、还拟投 Anthropic 最高 $40B，却让工程师改用 Claude 写代码——继 Amazon 之后第二家巨头低头，编码能力已成刚需。
      • 货架化正在发生：微软 Copilot 把 OpenAI / Anthropic / xAI 三家并排上架，用户按需选。「模型」是货，「货架 + 路由 + 治理」才是产品。
      • 护城河向两端跑：上移到编排 / 多模型路由 / 身份配额审计（control plane），下移到「谁的模型真能干活」的能力事实与私有数据。
      • 发布会不再等于领先：Gemini 3.5 Pro 半年跳票、Grok 4.7 七周三次跳票，说明「按时交付能干活的模型」本身就是稀缺；能力事实与交付纪律取代 PPT。
      • 对 FDE 的意义：别把「我们接了 X 模型」当卖点；把工程预算投到多模型路由与评测归因、可控性与合规治理，并在技术方案里默认「模型可替换」。

      一触发：自研旗舰厂开始用脚投票#

      — WHY NOW · 连做模型的公司都改用对手的模型

      过去两年，AI 竞争的隐含假设是「有一个足够好的自研模型 = 有护城河」。所以 Google 花数十亿建 Gemini、要求员工只用自家工具，微软深度绑定 OpenAI。但 2026 年 9 月这一周，几个动作把这个假设撕开了口子：

      • Google（09-15，Business Insider）：向全公司工程师开放 Anthropic Claude（Opus 5，经内部平台 Antigravity，按人配额）。此前 Claude 仅限 DeepMind 等少数团队。背景：Gemini 3.5 Pro 自 5 月预告后跳票、编码仍落后，而 Google 还宣布拟向 Anthropic 投资最高 $40B——一边投钱、一边让员工用它的模型。
      • Amazon（今年早些时候）：已先一步允许员工使用 Claude 与 OpenAI Codex。Google 这步被普遍解读为对同一竞争压力的跟进。
      • 微软（09-14）：把 xAI Grok 加进 Copilot 与 Microsoft 365，Word/Excel/PowerPoint 里可选 OpenAI 之外的模型。Nadella：「更多模型选择来到 Copilot，欢迎 Grok！」

      三件事指向同一个方向：在「模型能不能干活」这件事上，连自研旗舰厂都不再为了「用自家的」而牺牲生产力。模型成了可以按任务替换的组件，而不是唯一入口。

      用脚投票：谁在把竞品模型请进门The "Feet" Have Voted

      三张证据卡按时间排列。共同点：都是有自研模型 / 有深度绑定的巨头，却主动为员工或用户引入对手的模型。

      二核心论点：接入商品化，能力事实为王#

      — 「有没有模型」退化成入场券

      「商品化（commoditization）」的定义是：一件曾经稀缺、能区分高下的东西，变成随处可得、彼此可替换的基础货。正在被商品化的不是「模型能力」，而是「模型接入」这件事——接哪个厂、走哪个 API、用不用自家的，越来越像在货架上取货，随时可换。真正稀缺、拉得开差距的东西被挤到两端：

      注意分辨

      商品化的是「接入某个模型」的动作，不是「某个模型在你业务上真能干成活」的事实。同一个货架，谁的模型在编码 / 长任务上真能收敛，差距巨大——这就是 Google 宁可用 Claude 的原因。货架抹平的是「接哪个」，抹不平的是「哪个真行」。

      于是竞争沿两个方向重构：向上——谁能把一货架的模型安全、可计费、可审计地编排/路由起来（多模型 control plane）；向下——谁的模型在真实任务里的能力事实更硬（而非发布会 benchmark）。夹在中间、只靠「我们接了某个明星模型」的团队，最先被抹平。

      三机制：货架前那道关卡才是产品#

      — 请求进来，先过路由与治理，再落到某个模型

      当模型可替换，价值就聚到「一个请求进来、如何被路由到该由谁来干、并且被允许怎么干」这道关卡上。它不是模型，而是模型之上的 control plane：按任务/成本/合规选模型（路由），并回答「哪个 agent 能改哪些系统、什么要人工审批、每个工作流花多少钱」（治理）。这正是本周 Microsoft / OpenAI / Salesforce 同时在推的「企业 AI 控制面」。

      多模型路由 + 治理关卡Route → Govern → Dispatch

      一个请求先进路由器（按任务/成本/合规选模型），再过治理关卡（身份 · 配额 · 审计），最后才落到货架上某个模型。中间这两段——不是模型——是可防御的产品面。

      四护城河向两端跑#

      — 上移到治理路由，下沉到能力事实

      接入被商品化后，可防御价值离开中间层，往两端聚集。下面两张卡把方向画出来——两端都要投，最不该投的是「中间那层：接了哪个明星模型」。

      向上 · 编排 / 治理 / 路由

      多模型 control plane

      • 路由：按任务 / 成本 / 合规，把请求派给最合适的模型
      • 治理：身份、配额、审批、审计——哪个 agent 能改哪些系统
      • 可计费：把每个工作流的 token 与成本讲清楚给财务
      • 越贴客户、越难被单一模型厂标准化 → 可防御
      向下 · 能力事实 / 私有数据

      谁的模型真能干活

      • 能力事实：在你这条业务的真实任务上收敛率、返工率——不是发布会 benchmark
      • 私有上下文数据：你的独占资产，喂进任何模型都增值
      • 评测归因：用你的口径持续量出「哪个模型/配置真行」
      • 平台给不了你的东西 → 可防御
      层商品化后的处境该不该投工程
      多模型路由 / 编排模型可换，路由与编排成为新战场重投
      治理 / 身份 / 审计企业落地的准入条件，平台各搞各的重投
      评测归因（你的口径）「谁真能干活」只有你自己量得准重投
      模型接入 / 选哪个明星模型已商品化，绑定单一模型的边际收益趋零别当卖点，默认可换
      模型能力事实 / 自研微调要么挑真能干活的、要么向下深挖视资源，向下深挖

      五对 FDE 的意义#

      — 把方案从「接了谁」改写成「怎么路由、怎么治理、谁真行」

      下一步（1–2 周）
      • 把「模型可替换」写进架构默认：接入层抽象成可切换的 provider，别让任何一个明星模型渗进业务逻辑；退出成本先算清。
      • 停止把「我们接了 X 模型」当卖点：对客户改讲多模型路由、治理审计、以及「我们怎么量出哪个模型在你场景真行」。
      • 把预算投到 control plane + 评测归因：路由策略、身份/配额/审计、以及用自己口径的持续评测——这些是模型厂抹不平的。
      • 用能力事实选型，而非发布会：为关键任务建一套自己的评测集，用它决定货架上谁上场；把 Gemini/Grok 跳票当作「交付纪律」信号纳入选型。
      • 新增一条尽调项：客户/合作方评估里加「多模型策略与单一供应商锁定风险」。

      六典型陷阱#

      — 商品化不是「随便接一个就行」

      风险
      • 把「多模型」做成「多份耦合」：没有路由抽象，接三个模型 = 三套散落的 if-else，换模型照样要动业务，反而更脆。
      • 用发布会 benchmark 替代能力事实：榜单分数与你业务上的真实收敛率脱节；不建自己的评测集，选型就是拍脑袋。
      • 治理缺位：模型随便换、agent 权限不清，审计和合规红线会在企业客户处直接卡死。
      • 忽视货架背后的账单：多模型路由的可观测性、数据出域、按量计费复利，和「运行时商品化」是同一批新账单（见姊妹篇）。

      七待验证问题#

      1. Google 开放 Claude 是「战术止血」还是「战略转向」？若 Gemini 4/3.5 Pro 补上编码短板，会不会再收回？
      2. 会不会出现可移植的多模型路由标准（跨厂的调用/治理语义），把货架的锁定风险降下来？还是各家继续各搞私有 control plane？
      3. 「能力事实」怎么被行业客观量化——除了各家自建评测集，有没有可信的第三方口径能供企业选型？
      4. 当微软/OpenAI/Salesforce 都在做「企业 AI 控制面」，这层会不会又被平台收编、重演「运行时被商品化」的剧本？（见姊妹篇）
