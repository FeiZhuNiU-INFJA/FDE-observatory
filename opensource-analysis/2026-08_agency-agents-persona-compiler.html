      agency-agents · 一台把 persona 分发到 16 种工具的纯 Bash 编译器

      270 个 Markdown 人格 + 两张 registry + 一套 pure-bash「编译 / 安装」管线：价值不在运行时，在分发工程与内容治理

      带 frontmatter 的 agent（17 个分部）
      16 工具
      编译目标：Claude Code / Cursor / Codex / OpenClaw…
      0 依赖
      pure-bash + 标准库 Python，兼容 macOS bash 3.2

      divisions.json + tools.json = 全站单一真理源
      核心结论：agency-agents 表面是「270 个 AI 专家人格的合集」，但真正值得拆的不是它的内容，而是它的分发工程。它把「同一份人格源文件」抽象成一台纯 Bash 写的编译器：从一个 Markdown 的 YAML frontmatter 出发，按 format（输出契约）/ installKind（安装机制）/ slugFrom（命名）三层解耦，投影成 16 种 AI 编码工具各自的原生格式——TOML、mdc、SKILL.md、甚至 OpenClaw 的 SOUL/AGENTS/IDENTITY 三文件工作区。它最聪明的一块不是编译器，而是内容治理：一个用 8-word shingle + 专有名词中性化的去重脚本，专门拦「换个地名 find-replace 灌水的假人格」。对我们（OpenClaw → 火山 MA 迁移）最有价值的，是它给出的两个现成范式——「统一 persona 源 → 分层工作区」的投影逻辑，和「registry 单一真理源 + CI 三方防漂移」的治理骨架。
      一页要点
      • 它是内容库，不是框架：全站只有 Markdown + Shell + JSON，无运行时、无进程、无模型调用。agent = 一段「人格 + 使命 + 工作流 + 交付物模板」的结构化提示词。
      • 两张 JSON 是全站真理源：divisions.json（17 分部）+ tools.json（16 工具的安装契约）。目录名 ≠ 分部。
      • format 是字节级契约：同名 format 保证输出完全一致——所以 claude-code 与 copilot 共用 identity，两个 skill-md 工具共用一个渲染器。
      • installKind 三态：per-agent（一 agent 一文件，13 个）/ roster（全合成一文件，2 个）/ plugin（构建产物，只能 CLI 装，1 个）。
      • OpenClaw 渲染器最特殊：不是拷贝，而是按 ## 标题关键词把一份 persona 拆成 SOUL.md（人格）/ AGENTS.md（操作）/ IDENTITY.md 三文件——这正是你迁移里要处理的分层。
      • 治理是它的隐藏亮点：originality 检测用 shingle + Jaccard 抓「find-replace 复制品」，现有库最坏相似度仅 ~1.5%，FAIL 阈值定在 40%。
      • 短板也清楚：专家性完全取决于 Markdown 写得好不好（无工具绑定、无能力验证）；NEXUS「多 agent 协作」只有剧本没有编排引擎（vaporware）；install.sh 手搓 TUI 已 55KB，pure-bash 逼近可维护性天花板。

      一它到底是什么#

      — 先把「框架」的误会去掉

      README 把它包装成「The Agency：一家随取随用的 AI 代理公司」——从前端巫师到 Reddit 社区忍者，270 个专家人格分成 17 个「分部」。但拆开看，它没有任何运行时：没有 Node server、没有 Python 服务、没有 orchestrator。一个 agent 就是一个带 YAML frontmatter 的 .md 文件，正文是「人格 / 核心使命 / 关键规则 / 交付物模板 / 工作流 / 成功指标」的结构化提示词。

      规模上，engineering 58 个、specialized 57、marketing 36 是三大主力；healthcare 只有 3 个。所有「专家性」都压在 Markdown 的写作质量上——这既是它轻量可移植的原因，也是它质量必然参差的结构性来源（见 第八节）。

      载体
      Markdown + Shell + JSON
      315 个 .md、9 个 .sh、4 个 .json。除了配套的独立 app（README 推荐安装），仓库本身零第三方依赖，脚本只用 pure-bash 与标准库 Python。
      形态
      人格名册 + 跨工具安装器
      价值 = 内容（270 人格）× 分发（编译到 16 种工具）。面向 C 端开发者的「人格市场」，有 FUNDING、中英双语 CONTRIBUTING、四条 CI。

      二数据模型：两张 JSON 是全站真理源#

      — single source of truth，CI 强制三方一致

      整个系统靠两个 registry 做单一可信源，并用 CI 把「磁盘目录 / 脚本数组 / 路径过滤」钉死一致。

      divisions.json 定义 17 个分部（label / Lucide 图标 / 品牌色）。它的 _note 讲得很清楚：并非每个顶层目录都是分部——integrations/ 是转换输出不是源、strategy/ 是无 frontmatter 的剧本，二者连同 examples/ / scripts/ 都在 NON_DIVISION_DIRS 里被排除。「一个分部必须至少含一个 frontmatter agent 文件」。

      tools.json 是更精妙的一张——16 个目标工具的安装契约。每个条目携带三个正交抽象：

      字段含义关键规则
      format渲染契约同名 format 保证字节级完全一致的输出——两个工具只有输出完全相同才能共享。claude-code / copilot 共用 identity；osaurus / antigravity 共用 skill-md。
      installKind安装机制上游真理：per-agent 一 agent 一文件 / roster 全合成一文件 / plugin 构建产物（不可字符串渲染，只能 CLI 装）。
      slugFrom命名来源name（从 frontmatter 名字 slug 化）或 source（用源文件名）。部分工具还带 slugPrefix: "agency-"。
      detect / dest探测 + 落盘怎么判断该工具已装（探测目录）、装到哪（区分 user / project 作用域，路径模板 {slug}）。

      这个设计的价值：加一个新工具 = 改 3 处（tools.json 加条目 + convert.sh 加渲染器 + install.sh 加安装器）+ 跑一致性检查，全程数据驱动，不散落硬编码。

      三技术心脏：pure-bash 编译器#

      — 一份 persona 源 → 16 种原生格式

      转换器 convert.sh 把每个 agent 源文件按 format 渲染。核心是一组 convert_* 函数，配合 lib.sh 里的 get_field / get_body / slugify（纯 awk 解析 YAML frontmatter，无 yq 依赖，兼容 macOS bash 3.2）。整条管线可以画成一台编译器：

      一个源、一次解析、按 format 契约分流到多个渲染器 —— 16 种工具去重后只需实现 13 个 渲染契约。

      几个值得注意的渲染策略，都藏着「适配深度不一」的工程判断：

      • Codex 走 TOML（convert_codex）：用 toml_escape_string 处理正文里的控制字符，防止产出非法 TOML。
      • OpenCode 需要 hex 颜色：resolve_opencode_color 把 frontmatter 里的 cyan 映射成 #00FFFF，无法识别的兜底 #6B7280。
      • Aider / Windsurf 是 roster：accumulate_* 把所有 agent 累积进单个 CONVENTIONS.md / .windsurfrules，而不是一 agent 一文件。

      一 agent 一文件
      每个人格渲染成一个独立文件/目录。主流机制，consumer 可字符串渲染。
      claude-code · cursor · codex · openclaw…
      roster · ×2
      全员合成一文件
      所有 agent 累积进一个合并文件。工具本身没有「子 agent」概念时用。
      aider → CONVENTIONS.md · windsurf → .windsurfrules
      plugin · ×1
      构建产物（CLI-only）
      不可字符串渲染的构建件，任何 consumer 都无法当字符串生成，只能走 CLI。
      hermes → agency-agents-router 插件

      安装器 install.sh（55KB）是全仓工程含量最高的一块——纯 bash 手搓的交互式 TUI 向导。lib.sh 的 TUI 层自己实现了 alt-screen、raw mode、逐字节读转义序列的 read_key（连「孤立 Esc vs 方向键」都用 1s 整数超时区分，因为 bash 3.2 没有小数超时）、无闪烁 draw_frame。它靠 detect_* 探测本机装了哪些工具，支持 --tool / --division 定向安装。

      四OpenClaw 渲染器：一份 persona 拆成三文件#

      — 与你的迁移最相关的一段代码

      大多数渲染器只是「换个包装拷贝」，但 convert_openclaw 不同——它逐行扫描正文，按 ## 标题的关键词把一份 persona 分流进两个桶：identity / communication / style / critical-rules / learning&memory 归入 SOUL.md（人格层），其余（mission / deliverables / workflow…）归 AGENTS.md（操作层），再从 frontmatter 的 emoji + vibe 生成 IDENTITY.md。这直接对应 OpenClaw 工作区的语义分层。

      同一套关键词规则被 lint-agents.sh 的 classify_header_target 复用 —— lint 与 convert 共享分类逻辑，防止规则漂移。
      对你的迁移（OpenClaw → 火山 MA）

      这段代码给了一个现成参照：如何把「统一 persona 源」投影成「OpenClaw 三文件工作区」。反向读——就是 MA 侧要吃下同类 persona 时，该怎么做「人格层 / 操作层」的分层拆解。你在 arkagent 里的 SOUL.md/AGENTS.md/IDENTITY.md 处理，可以直接对照这套关键词分类规则做取舍。

      五质量护栏：内容库当工程治理#

      — 全仓最聪明的一块

      四条 CI（check-divisions / check-tools / check-runbooks / lint-agents）把「数据源一致性」钉死。最有洞察力的是 originality 检测——它针对「270 个人格靠改地名/平台名 find-replace 灌水」这个规模化必然出现的治理风险，用实体中性化的 shingle 相似度拦假人格。

      关键一招在第 1 步：把 vietnam / tiktok / wechat / shopee… 等专有名词中性化再比对，所以「换个国家名的复制品」藏不住。见 ENTITY 正则 + shingles(k=8)。

      lint-agents.sh 则校验 frontmatter 必填（name/description/color），并预演 OpenClaw 拆分逻辑：若一个 agent 的 ## 标题没有任何一个能映射到 SOUL 或 AGENTS，就 WARN——lint 与 convert 共享同一套 classify_header_target，防止规则漂移。它甚至在注释里记录了踩过的坑（grep -q 触发 SIGPIPE，在 pipefail 下伪装成「无匹配」）。这套「registry 单一真理源 + CI 三方防漂移」的模式，画出来就是一个一致性闸：

      六编排层：NEXUS（纸面协作）#

      — 有剧本，没有引擎

      strategy/ 提供了一套「如何把这些 agent 组合起来干活」的剧本，但要明确——这层是纯文档，没有可执行的编排引擎：

      • 6 阶段 playbook：discovery → strategy → foundation → build → hardening → launch → operate。
      • 4 个场景 runbook，如 startup-mvp：把 18–22 个 agent 编成「核心 / 增长 / 支持」三队，按周排布，带质量门（Reality Checker 终审）。
      • handoff 模板：handoff-templates.md 标准化 agent 间交接文档，明确点出「上下文丢失是多 agent 协作失败的头号原因」。

      这是它的野心，也是它的短板：编排靠人照着剧本手动激活 agent，没有 orchestrator 实际调度。README 里「18 个 agent 协同」的叙事，落地是人肉编排。

      七对我们的映射（LIFT / MA 迁移）#

      — 能直接抄的两个范式

      它的做法对应我们的问题可复用点
      OpenClaw 三文件拆分（convert_openclaw） OpenClaw → 火山 MA：persona 如何分层落地 「统一源 → 人格层/操作层」的关键词分类规则，可反向指导 MA 吃下 persona 的拆解
      registry + 一致性 CI（tools.json + check-*.sh） arkagent 的 divisions / bindings 表、userOpenId/vaultId 绑定 「单一真理源 + 防漂移三方校验」骨架；加一个工具/绑定就是固定的「改 N 处 + 跑校验」
      shingle + 实体中性化去重 内容/配置规模化后的重复与灌水检测 把「近似重复」当工程问题：8-word shingle + Jaccard 是低成本、可 CI 化的现成方案
      format 字节级契约（去重渲染器） 多目标产物的一致性保证 「同名 format = 输出完全一致」的约束，避免为每个目标各写一套易漂移的渲染

      八取舍与陷阱#

      — 一句话：分发工程扎实，内容与编排是短板

      亮点

      分发抽象干净、零依赖。format / installKind / slugFrom 三层解耦，pure-bash + 标准库 Python 兼容 macOS 3.2。加工具是数据驱动的固定动作。

      亮点

      治理意识超前。originality 去重 + lint/convert 共享规则，对「内容库规模化后必然的质量腐化」有真正的防御，而不是靠人肉 review。

      存疑

      本质是提示词库。专家性全看 Markdown 写得好不好——tools 字段大多为空、无能力边界验证、无回归测试。改一版 persona 的效果无从量化，质量参差是结构性的。

      存疑

      编排是 vaporware + 可维护性天花板。NEXUS 只有剧本没有引擎；install.sh 手搓 TUI 已 55KB，pure-bash 继续加功能会很痛——这也是他们另做配套 app 的原因。

      用它时的陷阱
      • 别当框架用：它不提供运行时/调度，装进你的工具后，agent 只是被激活的提示词，能力上限仍是底层模型。
      • 别迷信「270 个专家」：数量不等于质量，挑用时按 originality 逻辑反查——高度雷同的人格实际价值有限。
      • roster 工具会污染全局：Aider/Windsurf 把所有人格合成一个 CONVENTIONS.md/.windsurfrules，全量安装会灌爆规则文件，按 --division 定向装。
