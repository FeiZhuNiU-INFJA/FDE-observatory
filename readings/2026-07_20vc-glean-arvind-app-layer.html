      源：Why OpenAI and Anthropic Won't Win the App Layer | Glean Founder Arvind Jain（20VC with Harry Stebbings · 2026-07-11 · 60 分钟）

      核心论点：Arvind Jain 从应用层玩家视角给出的判断是——前沿模型公司不会赢下应用层，不是因为他们做得不够，而是因为「消费型计价 + 机构学习归属」这两件事，天然反捆绑、反前沿垄断。开源在近三个月刚刚跨过前沿门槛，成本差整整一个数量级；接下来三年，企业绝大多数负载会转到开源上——而这场迁移的门票，是谁能把「上下文」和「机构学习」握在自己手里。
      一页要点
      • 模型层正在商品化，但不是廉价化。90%+ 用例开源模型（含中国 GLM 5.2）已能覆盖；但过去 6–9 个月 token 价格在涨，因为模型公司要 IPO 前证明是「好生意」。
      • Bundling 不再是有效策略。过去微软靠 70% 品质 + 打包卖爆企业；一旦转为按消费计价，捆绑不再有内在优势——「用户在哪里干活我就为哪里付费」。
      • 应用层护城河 = 机构学习归属。企业的做事方式、隐性流程、跨年沉淀会积累在 运行 Agent 的那个人手里；把它交给前沿模型公司 = 交出运营主权。
      • 「用 AI 替代自己」是错误目标。竞争对手也有同样的工具，他若不裁员而是做十倍好的产品 / 出十倍多的货，你就输了。Glean 自己一千人、五年目标五千人。
      • AI 投入 ROI 是吞吐问题，不是替代问题。Glean 内部 ~100% 代码由 AI 写，但依然强制人工审查；瓶颈从写代码转到 review code。
      • 企业 AI 使用是幂律。5% 员工一月消耗 $10K-15K token，剩下 95% 只用来问答摘要；token 上限仪表板反而是错误激励。
      • OpenRouter 用量前六是中国开源，第七才是 Anthropic。美国开源真空是现实，但靠监管封中国模型救不了——「开源社区不需要天量预付投资，模型需要」，这是结构差。

      一Bundling 时代结束#

      — WHY THE APP LAYER IS SAFE

      Jain 用一段话把整场访谈的地基打稳：「一旦转向消费计价，捆绑就没有内在优势了。作为企业我可以提供六种工具，让员工选择在哪里干活；他们在哪儿干，我就为哪儿付费。」—— 这句话是他敢正面回应 Harry 的「Anthropic 会不会 Figma 掉你」的核心逻辑。

      过去二十年 SaaS 的护城河很大一部分是套餐即锁定：CIO 已经采购了 M365，就懒得再审批第 15 家供应商，微软以 70% 品质就能吃掉市场。但当每一次 API 调用都单独计费、账单能倒推回每个 Agent 每个 token 时，Bundling 卖出去的不是使用，是可能性——而可能性在按量付费世界里等于零。

      过去 · Bundling

      套餐即锁定

      谁能进供应商白名单，谁就赢——套餐里塞什么无所谓，反正一次审批打包过。

      → Consumption
      今天 · Consumption

      按 token 计价，捆绑失灵

      六款工具都摆出来，用户在哪一格干活，那一格才拿到钱——套餐里的另外五格是浪费。

      "作为一家企业，我可以提供六种工具让用户选择在哪里完成工作；无论他们在哪儿工作，我都必须为那项工作支付费用。"

      这个转移不是纸上推演——Jain 在访谈中被 Harry 直接问「微软和 Frontier 谁是更强的对手」，他给出的答案是「现在还早，但过去几年你至少经常听到『我买了 M365 Copilot 所以不看你了』的反馈」。捆绑现在还在锁死一部分订单，但每多一个按量计费的用例，这个锁的钥匙就少一颗。

      二三层护城河 · 机构学习决定 Agent 主权#

      — WHERE THE APP LAYER'S DEFENSE ACTUALLY SITS

      Jain 反复回到一个概念——「机构学习」（institutional learning）。他讲得比 Harry 引导他讲得更慢，说明是他真正在意的护城河。逻辑是这样：当你第一次做一项任务时你会记录十步流程，之后随着一次次执行你会不断调优；很多东西没被写下来，只是在做的人脑子里沉淀成了经验。这些经验会实时应用到之后的每一个案子上。

      问题是——如果这些 Agent 是前沿模型公司在替你运行的，那这些跨年沉淀的机构学习是积累在他们那里的，不是你的。「你完全依赖于这些 AI 公司来完成你的工作。」他说得含蓄，但这是应用层公司敢于面对 OpenAI / Anthropic 的第一根钢筋：谁运行 Agent，谁拥有它多年的学习。

      L1
      Model Capability

      推理、代码、语言、多模态。GPT / Claude / Gemini / GLM 5.2 都在这一层拉锯。谁能买到，谁就有。

      供应侧 · 商品化
      L2
      Context Assembly

      从企业几百个系统里搜出正确材料，拼成模型能吃的上下文——Glean 说自己"最先做企业级 RAG 和语义搜索"就是在守这一层。原始 MCP 是"暴力上下文组装"，代价是慢和贵。

      应用层 · 有工程壁垒
      L3
      Institutional Learning as Moat

      Agent 在公司里跑了一年之后，它学到的隐性流程、异常处理、术语校准——这些沉淀属于谁，决定了主权。交给前沿模型公司 = 交出运营依赖。

      主权层 · 不可迁移

      这个论点最有趣的推论是——Agent 不是一个纯软件，它是一个「和你共同经营了几年的员工」。软件替换成本是数据迁移；Agent 替换成本 = 从零开始训练一个新员工。这也是为什么 Jain 敢正面接 Harry 的追问：「你不担心 Anthropic 进来做企业？」他说：「我们每天都在和 Claude Enterprise 竞争，但那是浅层的问答；他们没有 L2 也没有 L3。」

      FDE 对读

      这套「机构学习不可迁移」在我们做 Loop Engineering 时也遇过：coding agent 跑得越久，它对代码库的隐性认知越厚，换 harness 等于扔掉这份认知。Jain 把它推到了企业 Agent 层面——所有真正跑通的企业 Agent 都会遇到这个「运行方=所有方」的暗默契约。

      三开源刚刚跨过门槛 · 但 CN 主导现实#

      — THE 6 : 1 QUESTION ON OPENROUTER

      访谈里最扎眼的一段数据来自 Harry——「Anthropic 现在是 OpenRouter 上美国第一个模型，排第七；前六都是中国的。」Jain 的回应很坦率：这不是「用不用开源」的问题，是「用不用中国开源」的问题；而后一个问题的答案，正在从"不敢"变成"敢"。

      他给出的时间戳非常具体：GLM 5.2 是他自己团队第一次觉得"可以放心把大部分企业负载放上去"的开源模型；这件事发生在采访前不到一个月。也就是说，2026 年 6 月是应用层公司集体开始「开源能不能替换 Anthropic」实测的月份——三年内绝大多数企业负载会转到开源上，是他给客户的口径。

      Jain 对「美国要不要有自己的开源模型」是明确态度：要——但不能靠监管。他给的两条论证：（1）开源社区的传统是"发热爱好者作品"，模型需要天量预付投资，两者结构不兼容；（2）现在唯一在美国之外产过顶级模型的国家是中国，法国等地做过尝试没能规模化——所以英伟达在花大钱推美国开源，这不是政治口号，是结构性缺项。

      Harry 的假设 · Jain 的婉拒

      Harry 追问「你不觉得 Sam 会给特朗普 5% 换来对开源的监管俘获吗？」——Jain 的回答是：「我更相信美国的制度性约束……而且现在也不需要限制开源，它在美国已经落后太多了。」这句话本身就是他对护城河策略的一致性表达：应用层公司要的是更多模型选项，不是更少。

      四AI ROI 不是替代问题 · 是吞吐问题#

      — WHY TRYING TO REPLACE YOURSELF IS THE WRONG KPI

      访谈中段是一场高强度的对撞——Harry 反复问：「你为什么不裁员？世界上最好的 CEO 都在缩规模。」Jain 的反驳很清晰：假设两家可乐公司都拿到同样的 AI 工具，一家裁掉一半人做同样多的事，另一家维持人数但做十倍好的产品——第二家会赢。

      这不是关于人多好还是人少好的老话——它嵌入 AI 之后有了新支点：AI 让每个人的产出上限抬高，同时把企业间的竞争门槛也抬高。Glean 自己的策略是"一千人 → 五年五千人"，而 Jain 反复强调："未来要从客户那里获得同样的收入，你必须做十倍好的产品。"

      把这个映射到 Glean 内部的操作：

      Glean 内部实践
      • 代码：几乎 100% 由 AI 写，但强制人工审查不废。瓶颈从"写代码"迁移到"review 代码"，这就是"吞吐问题"的精准形态。
      • 发布速度：没有显著提高——因为团队更大、成员更资深；发布速度是团队生产力问题，不是编码速度问题。
      • Every-hands / 全员：周会上高管必须演示"这周我用 AI 做的一件事、被 AI 替代的一件事"——不是 KPI 硬压，是"文化 shame & showcase"。
      • Token 上限仪表板：他明确说"我们不会做"——那是在奖励消耗更多 token 的人，是错误激励。

      还有一个数据点值得单拎——Glean 有个工程分诊 Agent，接管了值班团队 95% 的告警工作。之前团队 15 人，现在 Agent 一个月烧 $100 万。Harry 问："这比 15 个工程师还贵吧？"Jain 承认："是的，甚至可能更贵。"—— 但这是他愿意付的价格，因为 Agent 是 24/7 而且没有职业倦怠。这是他"AI 不是替代成本、是吞吐工具"的具象。

      五企业 AI 使用是幂律 · 95% 停在检索#

      — THE POWER LAW INSIDE EVERY COMPANY

      Harry 问"你看到人们疯狂用吗？"—— Jain 直白："人们没有拥抱它。"具体数字是：有些人一个月消耗 10,000–15,000 美元 token，另一些人只用 20 美元。这不是均匀分布，是硬幂律。

      Top 5% · Power Users
      $10K–15K/月 · token 消耗

      在高级用例上（Agent 编排、跨系统操作、代码 loop）真正把 AI 用起来。这是吞吐提升的载体。

      Bottom 95% · Casual
      ~$20/月 · token 消耗

      只做检索、问答、摘要——AI 世界的今日最大用例。用是用了，但离"取代人力"很远。

      这个幂律有两个战术推论：

      • 不要按人头做 token 预算。它不是均匀成本，是长尾分布——一刀切上限会砍死最能产生 ROI 的 5%。
      • 产品要设计"从检索 → 到 Agent"的爬升路径。95% 的人现在停在检索，是因为下一步的 UI / 工作流断了。这本身是应用层公司的下一个 UX 命题。

      Jain 的干预方式也值得一记——Glean CEO Nikesh（联合创始人）每周主持一场领导层例会，每位高管当场演示"这周我用 AI 做了什么"。这是把"5% Power Users"从员工层拉到管理层，让文化从上而下地扩散。

      六对 FDE 的映射#

      — WHAT WE TAKE HOME

      Jain 的判断对 FDE / 我们的影响时效
      模型层商品化 + Bundling 失效 企业客户会主动要求"多模型选路"能力（自动挑价廉质稳的）。LIFT 的接入契约应当默认支持跨模型评测——L2 采集要在模型侧解耦。 进行中
      机构学习决定 Agent 主权 归因分析器（内置 in LIFT）的价值放大——只有能把跨年 trace 沉淀成结构化"错误库 / 校正规则"的框架，才能把机构学习交回客户手里。这是我们"锅与品菜师"叙事的第二根钢筋。 6–12 月
      90%+ 用例开源覆盖 + GLM 5.2 门槛 Bench 的模型评测必须加中国开源系（DeepSeek / GLM / Qwen / Kimi）。否则我们的报告在 2027 年会被视为"偏见样本"。 1–2 年
      AI ROI 是吞吐问题 企业客户询问"AI 有没有省人"时，评测报告要能用 "同人数 ΔTurns / ΔTools" 这类交互效率指标回答，而不是"节省多少 FTE"。这与我们已经确立的 80% ΔTurns% + 20% ΔTools% 指标权重直接呼应。 已发生
      使用幂律 · 5% Power / 95% Casual 评测采样不能按人头均匀采——需要先分层再采样（Power Users 的 trace 才是评测样本的高价值区）。归因报告也要区分 Power / Casual 两个不同的错误模式。 进行中

      七可疑点 · Jain 的立场偏差#

      — WHAT TO DISCOUNT

      立场提醒

      Jain 是应用层玩家（Glean 估值 $7.2B）——他讲「模型公司赢不下应用层」的核心利益就是应用层。听他的话需要打两个折扣：

      • "消费型定价必然扩散"是他的希望——但 OpenAI / Anthropic 完全可以推 Enterprise 定额包（M365 就是这样）来把 Bundling 逻辑续上；Jain 自己在访谈中也承认微软是他"最主要的竞争对手之一"。
      • "90%+ 用例可跑开源"——这是"我们已经能选路"的说法，不等于"客户已经全在跑"。他给出的时间戳（GLM 5.2 一个月前刚过线）恰恰说明：这件事还非常新，样本不够。
      • OpenRouter 前七的百分比 Jain 没给——第 6 名和第 7 名之间可能只差 1%，也可能差一个量级。Harry 在这里没追问具体数字，是访谈的一个空白点。
      • "5% 员工消耗 $10-15K token"是 Glean 内部数字，未必迁移到其他行业——制造业 / 传统零售的分布很可能更陡（1% 而不是 5%）。

      但这些折扣不动他的骨架论断——Bundling 失效 + 机构学习护城河 + 中国开源真实性这三件事是硬事实，不是 Glean 视角的产物。

      八待验证 5 问#

      — WHAT TO WATCH IN NEXT 6 MONTHS

      1. OpenRouter 用量的百分比分布是什么？第 1 名占 30%？还是所有前六加起来才和第七 Anthropic 打平？—— 拉一次 OpenRouter 官方数据自己看。
      2. GLM 5.2 的企业实测跑通了没——三个月后我们该看到几个应用层公司出"从 Claude 切到 GLM 后 ΔTurns / ΔCost"的数据。找一两个 case study 追踪。
      3. Sam Altman 给特朗普 5% 的传闻是否演化为具体监管动作？—— 这决定了美国开源真空期是 3 年还是 5 年。
      4. "机构学习交给谁"的合同条款会不会成为下一代企业 AI 采购的必审项？—— 观察大型企业 RFP 中"Agent 学习数据的知识产权归属"是否开始出现。
      5. Token 消耗幂律是否收敛？—— Casual 95% 是否会因为 UI / workflow 改进爬升到 20%–30%？还是永远停在 5%？这决定了应用层公司下一步产品 roadmap 的重点。
